How the pieces fit

  • One Docker container runs everything: this web page, the API, the MCP endpoint your AI clients talk to (/mcp), and the FluidSynth renderer with a General MIDI soundfont.
  • Songs, renders, exports and your templates live in one folder mounted at /data (on TrueNAS: a dataset).
  • An access token protects everything except /healthz and these help pages. It is generated on first start and saved as token.txt in the data folder.
  • The image is published by you to ghcr.io/<github-user>/midimcp with the scripts below. No paid services or GitHub Actions are used.

Install on TrueNAS SCALE (fresh)

TrueNAS SCALE 24.10 or later. Menu names can shift slightly between releases.

  1. Make a dataset. Datasets → your pool → Add Dataset → name midimcp, preset Apps → Save. It appears at /mnt/<pool>/midimcp.
  2. Install the app. Apps → Discover Apps → ⋮ → Install via YAML → name midimcp → paste this, changing only YOUR_POOL: 
    services:
  midimcp:
    image: ghcr.io/bgoldbeck/midimcp:latest
    pull_policy: always
    restart: unless-stopped
    user: "568:568"
    ports:
      - "8765:8765"
    volumes:
      - /mnt/YOUR_POOL/midimcp:/data

    Port 8765 taken? Change only the left number, e.g. "8770:8765".

  3. Get the token. Apps → midimcp → Logs (under "Generated access token"), or in System → Shell: 
    sudo cat /mnt/YOUR_POOL/midimcp/token.txt
  4. Open the web UI at http://<nas-ip>:8765/ and paste the token once.
  5. Check it from any PC: 
    curl http://NAS_IP:8765/healthz

    Expect "status":"ok" and "audio":true.

No published image yet? Use this YAML instead; TrueNAS builds the image from GitHub (a few minutes):

services:
  midimcp:
    build:
      context: https://github.com/bgoldbeck/MidiMCP.git#main
    image: midimcp:latest
    restart: unless-stopped
    user: "568:568"
    ports:
      - "8765:8765"
    volumes:
      - /mnt/YOUR_POOL/midimcp:/data

Install with plain Docker (any Linux, Windows or Mac)

Option A: run the published image. Make a data folder the container user (UID 568) can write, then start it:

mkdir -p ~/midimcp-data && sudo chown 568:568 ~/midimcp-data
docker run -d --name midimcp --restart unless-stopped \
  -p 8765:8765 -v ~/midimcp-data:/data \
  ghcr.io/bgoldbeck/midimcp:latest
docker exec midimcp cat /data/token.txt

Docker Desktop on Windows/Mac: skip the chown and add --user root if the logs say the token file cannot be created; or run as yourself with --user "$(id -u):$(id -g)" on Linux.

Option B: build from source with Docker Compose.

git clone https://github.com/bgoldbeck/MidiMCP.git
cd MidiMCP
docker compose up -d --build
docker compose exec midimcp cat /data/token.txt

Data goes to ./data. Compose reads PUID, PGID, MIDIMCP_DATA_PATH, MIDIMCP_PORT, MIDIMCP_TOKEN and MIDIMCP_LOG_LEVEL from your environment or a .env file.

On TrueNAS add them to the YAML under the service: environment: { MIDIMCP_TOKEN: "…" }.

Connect AI clients

Endpoint http://NAS_IP:8765/mcp with header Authorization: Bearer YOUR_TOKEN. Replace both below.

Claude Code

claude mcp add --transport http --scope user midimcp http://NAS_IP:8765/mcp --header "Authorization: Bearer YOUR_TOKEN"

Stop the per-tool permission prompts by allowing mcp__midimcp in your Claude Code permissions.

OpenAI Codex: add to ~/.codex/config.toml, then set MIDIMCP_TOKEN in the shell Codex runs in.

[mcp_servers.midimcp]
url = "http://NAS_IP:8765/mcp"
bearer_token_env_var = "MIDIMCP_TOKEN"

Google Antigravity: Agent panel → … → MCP Servers → Manage → View raw config:

{
  "mcpServers": {
    "midimcp": {
      "serverUrl": "http://NAS_IP:8765/mcp",
      "headers": { "Authorization": "Bearer YOUR_TOKEN" }
    }
  }
}

Clients without HTTP MCP support can bridge with npx -y mcp-remote http://NAS_IP:8765/mcp --allow-http --header "Authorization: Bearer YOUR_TOKEN". After an update that adds tools, restart the client so it sees them. Full guide: docs/agents/connect-agents.md.

Updating

  • TrueNAS: after a new image is published, Apps → midimcp → Update (or Restart; pull_policy: always fetches the new latest). Or let the nightly auto-update do it.
  • Plain Docker: 
    docker pull ghcr.io/bgoldbeck/midimcp:latest
docker rm -f midimcp
docker run -d --name midimcp --restart unless-stopped -p 8765:8765 -v ~/midimcp-data:/data ghcr.io/bgoldbeck/midimcp:latest
  • Compose: git pull && docker compose up -d --build.

Songs are never touched by updates. Older song files load in newer versions; a newer song file is refused (not misread) by an older version.

For developers

Python 3.11+. Audio tests need FluidSynth and the FluidR3 GM soundfont (sudo apt install fluidsynth fluid-soundfont-gm lame); browser tests need Node.js 20+ and Playwright with Chromium. Missing tools make those tests skip, not fail.

Set up (Linux / macOS; on Windows use py -m venv .venv and .venv\Scripts\Activate.ps1):

git clone https://github.com/bgoldbeck/MidiMCP.git
cd MidiMCP
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"

Run the server locally (web UI at http://localhost:8765/):

MIDIMCP_TOKEN=dev-token-0123456789 MIDIMCP_DATA_DIR=./data python -m midimcp serve

For a client that only speaks stdio MCP: python -m midimcp stdio.

Checks (all must pass before a pull request; there is no hosted CI):

python -m ruff check .
python -m ruff format --check .
python -m pytest

Workflow: one branch per change named feature/…, fix/… or docs/…, starting with a pushed "Start:" commit; run the checks; open a pull request into main describing what changed and how it was tested; merge. Design notes live in docs/reference/, the feature order in docs/ROADMAP.md.

Where things are: src/midimcp/service/ (the only code that changes songs), mcp_server.py (AI tools), web_api.py + web/ (this UI), render.py (FluidSynth), templates.py + template_styles.py, music/ (theory, timing, expression), tests/, web-tests/.

Building and publishing the image

You publish to the free GitHub Container Registry from your own machine. You need a GitHub classic personal access token with only the write:packages scope (GitHub → Settings → Developer settings → Personal access tokens).

Windows (Docker Desktop in Linux-containers mode + Git for Windows): double-click scripts\publish-image.cmd, or from a terminal:

scripts\publish-image.cmd

Options: -NoPush (build only), -RefreshBase (take Ubuntu security updates; uploads everything), -Owner name. Output is colored and saved to publish-image.log.

Linux / TrueNAS shell:

sudo bash scripts/publish-image.sh

Options via environment: GHCR_OWNER=name, GHCR_TOKEN=… (otherwise it asks; paste with Ctrl+Shift+V in a browser shell), REFRESH_BASE=1. The working tree must be clean so the image matches a commit.

Both scripts tag latest, the version and the commit, push, and log out again. First time only: make the package public at github.com/users/<you>/packages/container/midimcp/settings (Danger Zone → Change visibility) so the NAS can pull without logging in.

Upload size: the image is split into layers that change at different rates, so a normal code change uploads about 1 MB. The soundfont and system packages (~450 MB) only upload again with REFRESH_BASE=1 / -RefreshBase or when a system package is added. Add new system tools to the "extra tools" line in the Dockerfile, never to the lines above it.

Nightly auto-update on TrueNAS

A cron job pulls the newest main, publishes the image if there is a new commit, and redeploys the app.

  1. Clone the source next to the data (once): 
    sudo git clone https://github.com/bgoldbeck/MidiMCP.git /mnt/YOUR_POOL/midimcp/src
  2. Save the GitHub token (input hidden; paste with Ctrl+Shift+V, then Enter), then lock it down: 
    sudo bash -c 'umask 077; read -r -s -p "GitHub token: " t; printf "%s\n" "$t" > /mnt/YOUR_POOL/midimcp/ghcr-token; echo; wc -c < /mnt/YOUR_POOL/midimcp/ghcr-token'
sudo chmod 600 /mnt/YOUR_POOL/midimcp/ghcr-token
  3. Test once by hand: 
    sudo bash /mnt/YOUR_POOL/midimcp/src/scripts/auto-update.sh
  4. Schedule it: System → Advanced Settings → Cron Jobs → Add: command bash /mnt/YOUR_POOL/midimcp/src/scripts/auto-update.sh, user root, schedule 0 4 * * *, hide standard output ✔, hide standard error ✘.

Log: /mnt/YOUR_POOL/midimcp/auto-update.log. Force a rebuild: sudo FORCE=1 bash …/auto-update.sh. Security updates (full upload): sudo REFRESH_BASE=1 FORCE=1 bash …/auto-update.sh.

Troubleshooting

  • Logs: "cannot read or create /data/token.txt": the container user cannot write the data folder. sudo chown -R 568:568 /mnt/YOUR_POOL/midimcp, then restart.
  • "audio": false in /healthz: the image lacks FluidSynth or the soundfont; republish it or use the build-from-GitHub YAML.
  • Publish fails: read the end of the log (sudo tail -n 30 /mnt/YOUR_POOL/midimcp/auto-update.log). Common causes: expired token, token without write:packages, no internet, disk full on the NAS.
  • Token file "must be mode 600": sudo chmod 600 /mnt/YOUR_POOL/midimcp/ghcr-token.
  • AI client can't connect: check curl http://NAS_IP:8765/healthz from the same PC, the token, and that the URL ends in /mcp.
  • Copy buttons on plain http:// addresses fall back to selecting the text: press Ctrl+C.

Security: don't port-forward 8765 to the internet. For access away from home use a VPN (e.g. Tailscale on TrueNAS).
